# 风筝节组通信中间件 (kitecomm)

一个用 Go 实现的组通信中间件教学/验证项目。裁判台、计分屏都是组里的成员，在
单进程内用事件驱动的“协程角色”模拟；网络延迟、乱序、丢包、分区、成员掉线/重连
都可以注入。带一个可视化页面，能看到每条消息在每个成员处的投递过程。

整个模拟跑在**单线程虚拟时钟 + 固定随机种子**上，因此同一场景每次运行逐事件
可复现，便于离线校验和回放。

## 目录结构

```
sim/      虚拟时钟调度器、故障注入网络、场景目录、模拟器运行时
proto/    成员协议栈：FIFO+NACK → 因果(向量时钟) → 两轮全序 → 视图冲刷
verify/   离线校验器：用发送记录重建真实依赖，逐条核对所有保证
web/      可视化服务与嵌入式前端页面
cmd/kitedemo/  命令行入口（verify / web 两个子命令）
```

## 协议栈分层

数据消息自底向上穿过四层，每层只依赖下层的保证：

1. **FIFO 可靠广播**。每个来源的信封带单调 FIFO 序号，接收方维护“下一个期望
   序号”，出现空洞就发 NACK 请求重传。发送方周期广播自己的 FIFO 水位
   (`FIFOAnnounce`)，这样连“最新一个包丢失、接收方不知道上界”的尾部丢包也能
   被发现并补回。
2. **因果序**。每条应用消息带向量时间戳。依赖未满足的消息进因果缓冲区，本地时钟
   推进后递归释放。判定时排除消息自身的向量分量。
3. **全序（两轮）**。每个成员对因果收到的消息回一个暂定序号（第 1 轮）；发送方
   收齐同视图所有成员的暂定序号后取最大值作为最终序号再广播（第 2 轮）。暂定序号
   最小且未拿到最终序号的消息是队首，它阻塞后面所有消息；最终序号相同则按发送方
   成员编号定先后。
4. **视图切换与冲刷**。最低编号成员（协调者）基于多轮心跳丢失发起怀疑。冲刷阶段
   收集所有幸存者持有的消息并集，已投递消息保留原最终序号，未投递消息按向量时钟
   拓扑排序分配新序号，保证有因果依赖的两条消息最终序号不会倒置。

## 关键语义对应需求

| 需求 | 实现位置 |
| --- | --- |
| 1. 发送序投递，丢包靠 NACK 补发 | `proto/member.go` FIFO 层 + `FIFOAnnounce` |
| 2. 因果序 + 向量时间戳 + 缓冲 | `proto/causal.go` |
| 3. 两轮全序、取最大暂定号、同号按成员编号、队首阻塞 | `proto/total.go` |
| 4. 全序不违反因果序 | `topoSortByVC` + flush 拓扑定序 |
| 5. 视图切换前补齐，幸存者投递集合相同 | `proto/flush.go` 权威重放 |
| 6. 无幸存者收到的消息判作废并回调 | `buildFlushComplete` 的 void 集 + `OnVoid` |
| 7. 掉线回来作为新成员、不带旧状态 | `sim/runtime.go` rejoin 分配新 id，安装时全量重置 |
| 8. 页面点消息看每成员被扣多久、卡在哪条 | `web/snapshot.go` + 前端下钻面板 |

## 运行

```bash
# 离线批量校验：36 个固定种子场景，全部通过才返回 0
go run ./cmd/kitedemo verify

# 可视化页面（默认 :8080，可传地址）
go run ./cmd/kitedemo web :8080
# 浏览器打开 http://localhost:8080
```

## 故障注入场景

`sim/scenarios.go` 内置 36 个场景，覆盖：干净基线、10%–50% 均匀丢包、宽延迟抖动
（强乱序）、单成员崩溃、崩溃后重连、双崩溃、网络分区与愈合、协调者分区、全局丢包
突发、不对称劣化链路，以及把所有故障叠在一起的 kitchen-sink 场景。每个场景都有
固定种子。

## 校验器检查项

`verify/verify.go` 独立于协议实现，只根据发送/投递事件回放：

- 每成员每视图的 FIFO（发送序）
- 用发送时向量时钟重建的因果序
- 全序：最终键一致性、同视图键唯一、投递流按键有序、成员间前缀一致
- 全序不反转因果依赖
- 同一视图内存活成员投递集合完全相等（崩溃成员不参与比较）
- void 消息绝不投递、且每条已发送消息要么投递要么 void
- 重连的新化身不投递任何旧视图消息
